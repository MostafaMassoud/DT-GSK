## 2. Research question and context

Defines the benchmark for the CEC 2011 Competition on Testing Evolutionary Algorithms on
**Real World Optimization Problems**: a curated set of real-world engineering and
scientific optimization problems (with MATLAB/C implementations) plus a common evaluation
protocol, so that stochastic optimization algorithms can be compared on practically
motivated problems rather than synthetic functions (preamble, p. 3).

## 4. Evaluation protocol (Section 2, pp. 39–40)

- Report **mean, best, and worst** objective values over **25 independent runs**.
- Record values after **50,000, 100,000 and 150,000 function evaluations (FEs)**.
- **Uniform random initialization** within the prescribed search space.
- Per-problem parameter tuning is discouraged; participants must document all adjustable
  parameters, dynamic ranges, tuning guidelines, tuning cost in FEs, and actual values
  used (p. 40, items a–e). Any encoding scheme must be problem-independent (p. 40).

Verification quotation (p. 40): "The authors should report the mean, best, and worst
objective function values obtained over 25 independent runs. The authors are asked to
report these values after executing their algorithms for 50000, 100000, and 150000 FEs."

## 5. Conservative findings

This is a benchmark-definition technical report: it defines problems and protocol; it
reports no algorithm results and declares no winner. Constraint handling is left to the
participant; several problems carry equality/inequality constraints beyond simple bounds
(Table 1, pp. 33–37).

## 6. Limitations

- No optimal values are certified for most problems (unlike synthetic CEC suites); the
  report gives literature-based context (e.g., best-known LJ cluster potentials, p. 5)
  but no per-problem f* table.
- The report predates later corrigenda/toolbox updates; the authoritative dimension/bound
  values for DT-GSK experiments are the vendored benchmark code, not this PDF, whenever
  the two are cross-checked (report is citation authority for suite identity/protocol).
- Some scanned-text artifacts ("tasted" for "tested", p. 4); formulas partly garbled in
  text extraction — cite by equation number and page, not by extracted text.
- The 42-page PDF contains no printed problem-count sentence like "22 problems"; the
  22-instance count is derived from Table 1 enumeration (pp. 33–37). If the manuscript
  says "22 real-world problems", anchor it to Table 1 as the enumeration.

## 9. Unsupported / prohibited overextensions

- Do NOT cite for any algorithm's CEC2011 competition result or ranking (report contains
  none).
- Do NOT claim the report certifies global optima or difficulty rankings of the problems.
- Do NOT attribute the "T01–T22" naming convention to this report; it numbers problems
  1–13 with 11.1–11.10. Map DT-GSK's internal 22-problem indexing to Table 1 explicitly
  if the manuscript needs the mapping.
- Do NOT cite it for a 51-run or 10,000·D-FEs protocol (that is CEC2013/CEC2017; CEC2011
  uses 25 runs and a fixed 150,000-FEs budget).
- If DT-GSK's experiments deviate from the official protocol (e.g., different run count
  or FEs), the deviation must be stated against this locator set, not silently implied
  as official.
