## 2. Research question and context

Defines the 28-function benchmark and the common experimental/reporting protocol for the
CEC 2013 Special Session on Real-Parameter (single-objective, bound-constrained)
Optimization, the successor of the CEC 2005 suite with newly developed composition
functions and modified base functions (Introduction/Section 1, PDF pp. 3–5).

## 3. Method — suite composition (Section 1, PDF pp. 4–34)

- All functions are minimization, shifted to a randomly placed optimum o drawn from
  [-80, 80]^D, scalable in D; common search range **[-100, 100]^D** (Section 1.1, PDF p. 4).
- Rotation matrices M1..M10 are orthogonal, generated by Gram-Schmidt from standard
  normal entries; data files provided for D = 2, 10, 30, 50, 100 (Section 1.1, PDF p. 4).
- Auxiliary transformations for ill-conditioning/asymmetry (Lambda-alpha diagonal
  matrix, T_asy, T_osz) are defined in Section 1.1, PDF p. 4.
- Table I (Section 1.2, PDF p. 5) lists all 28 functions and their shifted optimum
  values f* (from -1400 to 1400 in steps of 100):
  - f1–f5 unimodal (Sphere; Rotated High Conditioned Elliptic; Rotated Bent Cigar;
    Rotated Discus; Different Powers);
  - f6–f20 basic multimodal (incl. Rotated Rosenbrock, Schaffers F7, Ackley,
    Weierstrass, Griewank, Rastrigin variants, Schwefel variants, Katsuura, Lunacek
    bi-Rastrigin, Expanded Griewank+Rosenbrock, Expanded Schaffer F6);
  - f21–f28 composition functions (n = 3 or 5 components, mostly rotated).
- Functions must be treated as **black boxes**: explicit equations may not be exploited;
  only D and the FEs budget are usable as known values (note under Table I, PDF p. 5).
- Individual definitions with properties per function: PDF pp. 6–34.

## 4. Evaluation protocol (Section 2, PDF pp. 35–39)

- 28 minimization problems; **D = 10, 30, 50** (10D/30D acceptable for initial
  submission; 50D required in final CEC 2013 version) (PDF p. 35).
- **51 runs per problem** ("Do not run many 51 runs to pick the best 51 runs").
- **MaxFES = 10,000 x D** (100k / 300k / 500k for 10/30/50D).
- Uniform random initialization; time-based random seed.
- All optima are inside the bounds; no search outside bounds needed.
- Termination: MaxFES reached or error below 1e-8; **errors smaller than 1e-8 are taken
  as zero** (PDF p. 35).
- Record function error value f(x) - f(x*) at 11 checkpoints
  (0.01, 0.1, 0.2, ..., 1.0) x MaxFES per run; report best, worst, mean, median, std of
  the 51 final errors (Results-to-record, PDF p. 35).
- Algorithm-complexity protocol: T0 (arithmetic loop), T1 (200,000 evaluations of f14 at
  dimension D), T2 (complete algorithm, 200,000 evaluations, 5 repeats, mean T2-hat);
  report T2-hat, T1, T0 and (T2-hat - T1)/T0 at D = 10, 30, 50 (PDF pp. 35–36).
- No per-problem parameter tuning; report parameters, ranges, tuning guidance, tuning
  cost, actual values (PDF p. 36). Results format: one 11x51 matrix file per
  function/dimension (Table II, PDF p. 37).

Verification quotation (PDF p. 35): "Runs / problem: 51 ... MaxFES: 10000*D ...
Terminate when reaching MaxFES or the error value is smaller than 10-8."

## 5. Conservative findings

Benchmark-definition report only: no algorithm results, no rankings. Its design choices
(shifted optima, rotation, black-box constraint, error-value reporting with 1e-8 floor,
fixed 51-run/10000·D protocol) define what "CEC2013-comparable" means for any later
comparison.

## 6. Limitations

- Typographical quirk: the report numbers both "Experimental Setting" and "Results to
  Record" as Section 2.1 (PDF p. 35). Cite by page plus heading name.
- The PDF is a ResearchGate re-upload with a cover page; printed page numbers are absent,
  so only PDF-page locators are reproducible.
- The suite is bound-constrained and synthetic; it certifies nothing about real-world
  problems (that is CEC2011's role).
- D = 100 is not part of the official CEC2013 protocol (only matrix data up to D=100 are
  shipped); official dimensions are 10/30/50.

  rotations) and its official protocol (51 runs, 10,000·D FEs, error-value reporting,
  1e-8 zero-threshold, black-box constraint).

  (2014/2017) inherit — but only as CEC2013's own convention; do not claim from this
  report that CEC2017 uses the same rules.

  CEC2013.
