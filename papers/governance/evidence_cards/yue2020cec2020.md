## 2. Research question and context

The report defines the benchmark and rules for the CEC'20 Special Session and Competition on
single-objective, **bound-constrained** real-parameter optimization. Its stated motivation
(p. 2) is that in the CEC'05, CEC'13, CEC'14 and CEC'17 sessions "the maximum allowed number
of function evaluations -- unlike problem complexity -- did not scale exponentially with
dimension"; this competition therefore "significantly increases the maximum number of allowed
function evaluations for 10 scalable benchmark problems beyond their prior contest limits,
with the goal of determining the extent to which this extra time translates into improved
solution accuracy" (p. 2). Participants may not use the analytic form of the functions (e.g.
to compute gradients), and surrogate/meta-models are excluded (p. 2).

## 3. Method -- suite composition (Section 1, pp. 2-11)

Ten minimization problems, all shifted to a global optimum `o` drawn uniformly in
`[-80,80]^D`, all rotated, all on the search range `[-100,100]^D` (Sec. 1.1, p. 2). Rotation
matrices are generated from standard normal entries by Gram-Schmidt ortho-normalization with
condition number 1 or 2, and variables are randomly divided into subcomponents because
"linkages seldom exists among all variables in real-world problems" (Sec. 1.1, pp. 2-3).

Table "Summary of the CEC'20 Test Suite" (Sec. 1.2, p. 3):

| No. | Class | Function | F_i* |
|---|---|---|---|
| 1 | Unimodal | Shifted and Rotated Bent Cigar (CEC 2017 F1) | 100 |
| 2 | Basic | Shifted and Rotated Schwefel's (CEC 2014 F11) | 1100 |
| 3 | Basic | Shifted and Rotated Lunacek bi-Rastrigin (CEC 2017 F7) | 700 |
| 4 | Basic | Expanded Rosenbrock's plus Griewangk's (CEC 2017 f19) | 1900 |
| 5 | Hybrid | Hybrid Function 1, N = 3 (CEC 2014 F17) | 1700 |
| 6 | Hybrid | Hybrid Function 2, N = 4 (CEC 2017 F16) | 1600 |
| 7 | Hybrid | Hybrid Function 3, N = 5 (CEC 2014 F21) | 2100 |
| 8 | Composition | Composition Function 1, N = 3 (CEC 2017 F22) | 2200 |
| 9 | Composition | Composition Function 2, N = 4 (CEC 2017 F24) | 2400 |
| 10 | Composition | Composition Function 3, N = 5 (CEC 2017 F25) | 2500 |

Fourteen basic functions are defined in Sec. 1.3 (pp. 3-5): Bent Cigar, Rastrigin, High
Conditioned Elliptic, HGBat, Rosenbrock, Griewank, Ackley, Happycat, Discus, Lunacek
bi-Rastrigin, Modified Schwefel, Expanded Schaffer, Expanded Rosenbrock plus Griewangk, and
Weierstrass. Hybrid composition ratios are given in Sec. 1.4-B (p. 8): F5 `p =
[0.3,0.3,0.4]`, F6 `p = [0.2,0.2,0.3,0.3]`, F7 `p = [0.1,0.2,0.2,0.2,0.3]`. Composition
weights, sigma and bias vectors are given per function in Sec. 1.4-C (pp. 9-11), e.g. F8
`sigma = [10,20,30]`, `lambda = [1,10,1]`, `bias = [0,100,200]`. The report notes explicitly
that the problems "should be treated as black-box problems" and that "the explicit equations
of the problems are not to be used" (p. 3).

## 4. Evaluation protocol (Section 2, pp. 12-16)

Section 2.1 "Experimental Setting" (p. 12) states verbatim:

- Problems: **10 minimization problems**.
- Dimensions: "For F1-F5 and F8-F10 **D = 5, 10, 15, 20**; for **F6 and F7, D = 10, 15,
  20**" -- i.e. F6 and F7 are *not defined at D = 5*.
- Runs / problem: **30** ("Do not run many 30-trial runs to pick the best run").
- MaxFES: **D = 5 -> 50,000; D = 10 -> 1,000,000; D = 15 -> 3,000,000; D = 20 ->
  10,000,000**.
- Search range `[-100,100]^D`; uniform random initialization within the search space, random
  seed based on time.
- Termination: "Terminate when reaching MaxFES **or the error value is smaller than
  10^-8**"; error values below 1e-8 are recorded as zero (Sec. 2.2, p. 12).

Section 2.2 (p. 12) requires the function error value `F_i(x) - F_i*` to be recorded at
`(D^(k/5 - 3)) * MaxFES` for `k = 0..15`, i.e. **16 milestones per run**, and the best,
worst, mean, median and standard deviation of the 30 runs at MaxFES. Section 2.2-6 (p. 14)
fixes the submission granularity and states the cell count explicitly:
**8 (F1-F5, F8-F10) x 4 (5D, 10D, 15D, 20D) + 2 (F6, F7) x 3 (10D, 15D, 20D) = 38 files**,
each containing a 16x30 matrix.

Section 2.3 (p. 13) defines the algorithm-complexity measurement (T0 from a fixed arithmetic
loop, T1 from 200,000 evaluations of Function 1, T2 the mean of five complete algorithm runs
at 200,000 evaluations; report `(T2_bar - T1)/T0` at D = 5, 10, 15).

Section 2.4 "Evaluation Criteria" (pp. 15-16) defines the competition score:
`Score = Score1 + Score2`, maximum 100. Score1 comes from `SNE`, a dimension-weighted sum of
normalized error values with weights **0.1 / 0.2 / 0.3 / 0.4** for 5D / 10D / 15D / 20D
(Eq. 22), normalized by the largest best-of-30 result across all algorithms (Eq. 23), scaled
by Eq. 24. Score2 is the identically weighted sum of **ranks** based on mean error (Eq. 25),
scaled by Eq. 26. The report notes: "Scores exclude F6 and F7 in the 5D case, hence the
summation limit of 8 for the first sum of both SNE and SR" (p. 16).

## 5. Conservative findings

This is a benchmark-definition technical report: it defines ten functions, the dimension
grid, the FE schedule, the recording format and the scoring formula. **It reports no
algorithm results and declares no winner.** Its own reference list (pp. 16-17) points to the
CEC 2005 / 2013 / 2014 / 2017 definition reports and to `li2013lsgo` (its reference [5]).

## 6. Limitations

- **The dimension grid is not rectangular.** F6 and F7 exist only at D = 10, 15, 20. Any
  table, mean, or rank that silently includes an "F6/F7 at D = 5" cell contradicts p. 12 and
  the 38-file count on p. 14.
- The report specifies **30 runs**. A 25-run or 51-run protocol is not this suite's protocol
  and any deviation must be disclosed against p. 12 rather than implied as official.
- The report defines a **score**, not a significance test. It supplies no statistical
  procedure (no Friedman, no Wilcoxon, no multiplicity control); statistical claims need
  the Appendix-B.8 keys.
- The scoring formula in Sec. 2.4 is defined **across the competing field** (`f(x_best)max`
  is "the largest f(x_best) among all algorithms"; ranks are "among all algorithms"). It is
  therefore not computable for a single algorithm in isolation and cannot be quoted as an
  absolute quality measure for one optimizer.
- Function definitions are cross-referenced to CEC 2014 / CEC 2017 functions rather than
  restated in full for every case; where a property matters, cite this report's own
  property bullets (pp. 5-12), not the parent suite.
- The report is silent on which shift/rotation data files are shipped for which dimension.
  An availability gap in a particular data distribution is an implementation fact and must
  never be presented as a protocol rule of this report.

## 8. Supported uses

- Citing the **CEC2020 suite definition**: ten functions, their unimodal/basic/hybrid/
  composition classes, the `F_i*` bias values, the `[-100,100]^D` range and the black-box
  rule.
- Citing the **official CEC2020 protocol**: 30 runs per problem, the per-dimension MaxFES
  schedule (50k / 1M / 3M / 10M for D = 5/10/15/20), uniform initialization, and the 1e-8
  termination/zero threshold.
- Citing the **dimension restriction** that F6 and F7 are specified for D = 10, 15, 20 only,
  and the 38-cell protocol grid that follows from it.
- Grounding the statement that CEC2020 deliberately raises the FE budget relative to earlier
  CEC bound-constrained suites.
- Grounding a disclosure that the manuscript's own statistical layer is *not* the
  competition's scoring formula, by pointing at Sec. 2.4 as the competition criterion.

## 9. Unsupported / prohibited overextensions

- Do NOT cite this report for **any algorithm's CEC2020 result, score or competition rank**
  (AGSK, IMODE, or otherwise). The report contains none.
- Do NOT cite it for a **25-run** or **51-run** protocol, or for `10,000*D` FEs; those belong
  to other suites. CEC2020 is 30 runs with the four-value MaxFES table.
- Do NOT present results for **F6 or F7 at D = 5** as protocol-conformant, and do NOT
  describe the grid as 10 functions x 4 dimensions = 40 cells; the report's own count is 38.
- Do NOT quote the Score / Score1 / Score2 formula as a per-algorithm quality measure: it is
  defined relative to the whole competing field.
- Do NOT use this report as the definition source for CEC2014 or CEC2017 functions merely
  because CEC2020 reuses them; cite `awad2016problem` (CEC2017) or the CEC2014 report for
  those suites' own definitions.
- Do NOT attribute any *statistical* method (Friedman, Wilcoxon, Holm) to this report.
- Do NOT use it to certify that a particular shift/rotation data distribution covers all 38
  cells; the report says nothing about data-file availability.
